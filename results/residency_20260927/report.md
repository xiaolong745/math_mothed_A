# Tensor 复用 / 宏块 / 驻留窗口受控实验

结论：第一版新增候选在 24 个组合上未超过当前 elite；最终全部保留原方案。这否定的是本次具体构造和评分，不能据此否定所有驻留优化。停止扩大搜索与全量运行。

## 范围与接口

- 远端 CPU，case_001、case_005 × 2/3/4/5 核 × P1/P2/P3，12 个独立 worker。
- 单 Tensor 对应一个逻辑页；不改输入、不复制或删除 Op，不模拟硬件页表。
- Tensor net 保留全部 pin；宏块按共享 Tensor 偏好从拓扑就绪节点构造，尺寸 8/32。这是受限的 tensor-net 贪心构造，不是完整全局超图优化器。
- 所有宏块与零字节依赖保留；P/C/Pi 合法性最终由完整官方 evaluator 确认。
- 驻留窗口只是工作集与访问优先级；不声称强制驻留、预测精确 Spill 或真实 FIFO 时间线。
- P3 官方 key 是 COPY_IN 目标 Tensor 的 logical_tid/ID；原始 DDR ID 相同不保证命中。
- P2/P3 在同核 Task 中按子图优先级重排 Step1 序，再由 Step2/Step3 处理，窗口不是独立 Task。
- 宏块结构哈希、搜索结果复用与完整超图划分暂未扩展；原 Portfolio 默认不变。

## 可定位的失败证据

- case_005/P2/k5 固定 P、C，仅改窗口顺序：53716 → 79559。Added DDR 均为 1867764，Spill 均为 0，跨核传输均为 804 条，每核 M/V 总工作量完全相同。这直接表明该窗口优先级损害调度时序；不是靠降低 Spill 获益的场景。实际 Pipe 空闲和结束时间见 timeline_diagnostics.csv。
- 同一组合 macro_32_heft：Added DDR 1867764 → 336490，但 Makespan 53716 → 103652。M 工作分配变为 [28944,420,34140,210,168]，出现明显负载集中；减少搬运没有抵消负载与依赖时序损失。
- case_005/P3/k5 固定 P、C 的窗口方案命中字节 537204 → 570322，Makespan 却从 47043 → 78204。命中改善不能当作最终时间改善。
- case_001/P2/k5 旧方案无跨核传输、Spill 为 0，每核 M 工作均为 46560；macro_32_heft 引入 312 条跨核传输且 M 分配不均，Makespan 47502 → 89250。
